# Architecture Decision Records

ADRs record durable, consequential decisions so the project does not repeatedly rediscover or silently reverse architecture choices.

## Status values

- `Proposed` — under review; implementation must not assume acceptance.
- `Accepted` — current decision and default for new work.
- `Superseded` — replaced by a newer ADR; retained for history.
- `Rejected` — considered and intentionally not chosen.

## Requirements

An ADR should document context, decision, alternatives, consequences, and explicit revisit conditions when useful.

Do not use ADRs as task lists. Implementation status belongs in GitHub issues/PRs.
